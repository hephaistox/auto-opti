* Security evaluation
Note: no =eval= / =read-string= / =load-string= / =slurp= / =spit= / shell-exec
sinks exist anywhere in =src/=. The surface is small and concentrated in PRNG
semantics.

** TODO 11. Document PRNG security boundaries (not cryptographic)
xoroshiro and the host built-in generators are NOT cryptographically secure. Add
explicit warnings to =auto-opti.prng= (and impl) docstrings and the prng wiki
page: never use for keys, tokens, password salts, or any security-sensitive
randomness; use a CSPRNG instead. Also document that the default fixed seed
(=#uuid "54b9758a-..."=) makes every default PRNG produce the identical stream —
intended for reproducible simulation, a footgun anywhere uniqueness is assumed.

** TODO 12. Resolve thread-safety contract mismatch and seed validation
=stateful/PRNG= docstring claims "thread safe to use", but the new clj map-of-fns
impls mutate a shared =long-array= with =aset= (no synchronization) and
xoroshiro256's own docstring says "Not thread-safe". Reconcile: either make the
contract honest (document single-threaded / per-thread instance, use
=duplicate=/=jump= for parallelism) or provide a genuinely safe variant.
Separately, harden seed handling: =auto-opti.prng/prng= calls =parse-uuid= on
string seeds, which throws on malformed input — add a Malli spec / graceful
validation for =::opti/seed= rather than an uncaught exception.
